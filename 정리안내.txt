COS 연구자료 정리 안내

1. 폴더 구성
00_보존목록: 전체파일목록.csv, 검증 기록, restore.py
01_최종제출물: COS_최종보고서.docx, 발표 PDF, 앱 시연영상, 오프닝영상
02_핵심연구: 최종 모델·외부 검증·전이학습·시각화의 열람용 복사본과 전체 목록
03_수집데이터_전처리: 원본 수집 자료·전처리·모델 입력 자료의 목록과 설명
04_이전연구_보관: 시행착오·이전 결과·이전 배포·백업의 목록
기존 app, eye, skin, transfer_learning은 실행 경로를 깨뜨리지 않도록 유지했습니다.

2. 반드시 알아둘 사항
일반 git clone / Download ZIP은 전체 백업이 아닙니다.
대용량 보존 ZIP은 같은 저장소의 Releases에 따로 있습니다.
https://github.com/seeum0121-debug/COS_project/releases/tag/research-preservation-20261121
해당 Release의 COS-preserved-*.zip 및 COS-preserved-*.zip.partNNN 파일을 모두 다운로드하고 00_보존목록도 함께 보관하세요.
COS-preservation-metadata.zip에는 복원 도구와 전체 목록이 포함되어 있습니다. 이 파일은 일반 압축 해제로 사용할 수 있습니다.
일부 ZIP은 전송 중단 시 재시도 비용을 줄이기 위해 100MiB 단위로 나뉘어 있습니다.
restore.py가 분할 파일을 순서대로 자동 조립하며 각 조각과 조립된 ZIP의 SHA-256을 모두 검사합니다.
분할 ZIP 조립에 임시 디스크 공간 약 1.5GB가 추가로 필요합니다.
ZIP 안의 이름은 SHA-256이며, 중복 내용을 한 번만 저장합니다. 원래 파일명과 경로는 전체파일목록.csv에 있습니다.
ZIP을 단순히 풀지 말고 restore.py를 사용해야 원래 경로로 복원됩니다.

3. 검증 / 복원 (Python 3.11 이상, 추가 설치 패키지 불필요)
검증만 실행:
python 00_보존목록/restore.py --archives "다운로드한 ZIP 폴더"
원래 폴더 구조로 복원:
python 00_보존목록/restore.py --archives "다운로드한 ZIP 폴더" --destination "새 복원 폴더"
복원 폴더 아래 COS와 제출물 폴더가 생깁니다. 기존 파일은 덮어쓰지 않습니다.
복원 시 모든 ZIP, 각 개별 파일 및 복원된 파일의 SHA-256을 확인합니다.
원격 보존 검증은 GitHub 서버가 계산한 SHA-256과 로컬 파일 해시·크기를 대조합니다.
첫 13개 ZIP은 전체 재다운로드 해시 대조도 수행했습니다. 모든 첨부파일을 다시 내려받았다는 의미는 아닙니다.
기존 코드의 상대경로는 복원 구조에서 유지됩니다. 원래 PC의 절대경로에 의존하는 코드나 외부 서비스는 별도 환경 설정이 필요할 수 있습니다.
모델 학습을 다시 실행해 모든 결과를 재현했다는 의미는 아닙니다.

4. 보존 / 제외 원칙
보고서·코드·모델·수집 데이터·이전 연구 결과·배포 산출물은 보존합니다.
재설치 가능한 Python 가상환경, 설치 의존성, __pycache__ 등 실행 캐시는 제외합니다.
연구용 cache 폴더는 이름만으로 제외하지 않습니다.
중첩 .git 내부 메타데이터는 제외합니다. 해당 로컬 저장소의 미푸시 커밋 이력·stash까지 백업한 것은 아닙니다. 실제 작업 파일은 보존 대상입니다.
상태와 제외 사유는 전체파일목록.csv에 파일별 기록되어 있습니다.
이 목록의 제외 항목까지 보존되었다고 해석하거나 무조건 삭제해도 된다고 해석하면 안 됩니다.

5. 데이터 해석 / 출처
NTP ICE 기반 연구자료, ChemExpo, PPIS, DailyMed, CSCP 등은 원본 경로와 기존 출처 정보를 유지했습니다.
최종/준비/학습용데이터/V5의 원본파일과 모델학습용은 서로 다른 단계입니다.
피부·안 자극성 EPA 라벨, Zein endpoint, 등록 경고 문구는 서로 대체할 수 없습니다.
기존 데이터 주의사항 및 공개자료원·다운로드 목록을 함께 확인하세요.
공개 열람 가능성이 자유 재배포 허가를 의미하지는 않습니다. 원문·외부 자료의 권리는 원 권리자에게 있으며 이 정리가 새 라이선스를 부여하지 않습니다.

6. 삭제 전 확인
보존검증.json에서 remote_verified가 true인지 확인하세요.
Releases ZIP 전체 다운로드와 복원 검증을 직접 마친 뒤 원본 삭제 여부를 결정하세요.
원본 COS 및 바탕화면 제출물에는 이 작업으로 삭제·이동을 수행하지 않았습니다.
